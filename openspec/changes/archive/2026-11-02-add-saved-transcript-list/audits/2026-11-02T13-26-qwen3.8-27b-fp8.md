### Findings

| ID | Category | Severity | Description | Evidence |
|----|----------|----------|-------------|----------|
| AC-1 | Accuracy | Error | Spec and design contradict on the list response shape | Spec L10 (requirement "Transcript list endpoint"): the endpoint "returns a **JSON array** of the persisted transcripts". Design decision 7 (L65): "`GET /api/transcripts` → `200 {"transcripts": [...]}` (**envelope object, not a bare array**, so fields can be added later…)" and task 2.1 follows the design ("returns `{"transcripts": [...]}`"). The normative spec text and the intentionally-chosen wire format disagree; as written, an implementer following the spec letter would fail the design/tasks. The spec line should be updated to describe the envelope before archiving (the delta folds into the main specs). |
| CM-1 | Completeness | Warning | Requirement clause has no scenario or test requirement | Spec requirement "Saved transcripts list section" (L160) states "the section SHALL provide a manual refresh affordance; there SHALL be **no automatic polling**." Scenarios T-016…T-020 cover display, prettified name, empty state, scrolling, and post-fetch refresh — none exercises the refresh button or asserts the absence of polling. Task 3.1 builds the refresh button but maps only T-016/018/019. |
| FS-1 | Feasibility | Warning | Design rationale contradicts the actual write flow | Design decision 6 (L57): "for a freshly fetched (not-yet-clicked) transcript the Download button is disabled — **there is no saved file to download yet**." But `app/main.py` L94–96 `await asyncio.to_thread(save_transcript, …)` *before* the fetch response returns, so in the normal case the file already exists when the UI renders the result. The UX constraint (download target only populated from saved-list rows) is sound because the fetch response carries no derived file name — the stated rationale is inaccurate and could mislead the implementer. |
| CO-1 | Coherence | Info | Design/tasks include work not listed in the proposal | Design decision 8 (L70) and task 4.1 add README changes (storage-section paragraph + `GET /api/transcripts` smoke-test step), but the proposal's "Impact" section lists only `app/main.py`, the read-side module, `app/static/*`, and tests. Minor scope observation; consider adding the README to the proposal's Impact. |
| CO-2 | Coherence | Info | Tasks have no mapped spec requirement | Tasks 4.1 (README update) and 4.2 (run full non-e2e + e2e suites) map to no requirement in `specs/transcript-library/spec.md` — implementation/detail and verification work, acceptable as-is. |
| VL-1 | Validity | Info | Test runner invocation inconsistent across artifacts | Design "Test Strategy → Run" (L77) uses `uv run python -m pytest …`, while all 25 Test Requirement blocks in the spec and all verification commands in tasks.md use bare `python -m pytest …`. The bare form matches the existing convention in `tests/e2e/test_ui.py`'s docstring ("Run:  python -m pytest tests/e2e/ -q"), so severity is low — note for consistency. |
